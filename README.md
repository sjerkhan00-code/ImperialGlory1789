# Imperial Glory 1789 — source

Source code of the Nexus Mods release **Imperial Glory 1789** (a 1789 world campaign for Imperial Glory, 2005):
https://www.nexusmods.com/imperialglory/mods/5

This repository contains no files of the original game and no decompiled code. Building the release needs your own
copy of Imperial Glory v1.1.

## What runs on the player's PC

Only the installer in [`installer/`](installer/), all plain text:

| File | What it does |
|---|---|
| `Install.bat`, `Uninstall.bat` | Two-line launchers: `powershell -NoProfile -ExecutionPolicy Bypass -File install.ps1` (the bypass applies to that one run only). |
| `install.ps1` | The offline installer. It finds the game folder, checks `ImperialGlory.exe` (size, MD5, and the original bytes of every patched range), and writes a patched copy named `ImperialGlory_ModNations.exe`. It never changes `ImperialGlory.exe`. Then it builds `Data2.pak` from the player's own `data.pak` / `Data1.pak` / `Text.pak` plus the files in `payload/`. Every file is checked by MD5, and anything it replaces is backed up. It has no internet access and changes no system settings. |
| `patches.json` | Byte ranges for the exe patch: offset, expected original bytes, new bytes. Generated by `tools/make_release.py` from `tools/nations.py` (`patch_exe`, where every patch is a numbered, commented block). |
| `manifest.json` | Every `Data2.pak` entry. Each entry is either copied from an original pak, an IGD1 binary delta of an original entry, or a new mod file, with its size, MD5 and CRC. Deltas and new files ship as loose files `payload/0001.dat ...`; the release zip contains no nested archives. |

There is no compiled code in the release (no .exe or .dll). The patched exe is produced on the player's PC from their own exe.

## Repository layout

| Path | What |
|---|---|
| `installer/` | the installer and its data (as shipped) |
| `tools/make_map.py` | the build: writes `build/public/Data2.pak` and `build/public/ImperialGlory_ModNations.exe` |
| `tools/nations.py` | nations, troops, texts, flags and all exe patches (`patch_exe`) |
| `tools/make_release.py`, `tools/igdelta.py` | the release package: `patches.json`, `manifest.json`, `payload/`, self-tests, zip |
| `tools/validate_build.py` | consistency checks of a build |
| `tools/art/`, `tools/lvl_*.py`, `tools/meshgen.py` | generators for the map art, unit textures, battle maps and meshes |
| `build/` | the mod's own data read by the build: translations (`i18n`), 1789 armies/economy (`start1789`), diplomacy (`diplo1789`), map geometry, battle map metadata, Natural Earth / world-atlas data |
| `release_texts/` | README, CREDITS and CHANGELOG of the release |

## Building the release

Requirements: Windows 10/11, Imperial Glory v1.1 (Steam), Python 3.12 with `pillow`, `numpy` and `capstone`
(`pip install pillow numpy capstone`).

1. Copy `data.pak`, `Data1.pak` and `Text.pak` from your game folder into `paks/`, and your `ImperialGlory.exe` to
   `re_tools/target/ImperialGlory.exe`. They are only read.
2. Extract the original paks: `python tools/extract_paks.py` (writes `data/`, `data1/`, `text/`).
3. Generate the art and battle maps once. These steps read the original game's textures and levels, which is why
   their outputs are not in this repository:
   - map tiles: `python tools/art/render_all2.py --force`, then `tools/art/deframe.py`, `tools/art/oldarea/northfix.py`,
     `tools/art/oldarea/render_borders.py`, `tools/art/islands/coastfit.py --apply`;
   - unit textures and icons: `python tools/art/units/cultures.py`, `python tools/art/icons/make_icons.py`;
   - battle maps: `python tools/lvl_region.py`, `python tools/lvl_caucasus.py`.
4. Build: `python tools/make_map.py --public` (about 5 minutes).
5. Check: `python tools/validate_build.py --public` (must print `OK`).
6. Package: `python tools/make_release.py --zip`. It writes `build/public/release/ImperialGlory1789_v1.0.0.zip` and
   self-tests the installer algorithm: the exe patch on both known v1.1 exes, refusal of a changed exe, a simulated
   install that must reproduce `Data2.pak` byte for byte, and a check that no payload file equals an original game file.
