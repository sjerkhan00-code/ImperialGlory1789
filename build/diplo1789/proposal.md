# Imperial Glory 1789: historical starting diplomacy and a more active AI

Research plus a data proposal. Nothing in `tools\`, `mod\`, `data\` or the exes was changed.
Everything was generated by `build\diplo1789\make_diplo1789.py` into `build\diplo1789\out\`, using the same paths as inside the pak.
The machine-readable version is `diplomacy.json`.

## 1. Where the starting diplomatic state lives

### Files
- `Game/GameModes/Gestion/defsInicialesJugadores.sb`
- `defsInicialesLocal{Easy,Medium,Hard}.sb`
- They are referenced as `DEFS_INICIALES_*` in `ModeloGestion.sb` (line 104 ff.).

### Loader
- The entry point is **FUN_0061c700**, at all.c ~431040-431075.
- It loads the Local file for the selected difficulty (`cfg+0x44`: 0 = Easy, 1 = Medium, 2 = Hard), plus `defsInicialesJugadores`.
- It then calls **FUN_0061c250**, which walks every player A and every other player B.
  - The human player's block (`cfg+0x1c`) is read from one document.
  - Every AI block is read from the other.
  - So the Local file is very probably used for the human's own block only.

### Format
This is the format from the file header, confirmed by the code (FUN_0061c250 and FUN_0061bf90):
```
.JUG_A
[
  .JUG_B [ .HOSTILIDAD 45.0 ]
  .JUG_C [ .HOSTILIDAD 40.0 .ESTADO_DIPLOMATICO [ .ESTADO PROTECCION_MUTUA .TURNOS 12 ] ]
  .JUG_D [ .HOSTILIDAD 92.0 .ESTADO_DIPLOMATICO [ .ESTADO GUERRA ] ]
  .JUG_E [ .HOSTILIDAD 40.0 .ESTADO_DIPLOMATICO [ .ESTADO PERMISO_PASO .TURNOS 8 ] ]
]
```

### What each field does
| Field | Code | Effect |
|---|---|---|
| `HOSTILIDAD v` | `FUN_00596d10(A,B,v)` **and** `FUN_00596d10(B,A,v)` (`rel[A][B]+4`) | Sets the value in both directions. A later block overwrites an earlier one, so **every pair must have the same value in both blocks**. |
| `ESTADO GUERRA` | `FUN_00596d30(A,B,0)` and `(B,A,0)` | State 0 = war, both ways. |
| `ESTADO PROTECCION_MUTUA .TURNOS n` | `FUN_0059c8a0(A,3,set)` | Collects A and all of A's current allies (state 3). If B is not in that set, **B gets state 3 and the turns (`+0x18`) with every member**. Alliances are therefore **blocs**: allying B to A also allies B with A's partners. |
| `ESTADO PERMISO_PASO .TURNOS n` | `rel[A][B]+0x10 = n` | One direction only; the state does not change. Write it in both blocks. |

What the loader cannot do:
- No other `ESTADO` value is parsed.
- Truce, coalition, commercial treaty, marriage and vassal or protectorate states **cannot be set as starting data**. State 2 = peace is set only at runtime (FUN_0068f110).

### Limits from `Reglas/DefReglasGenerales.sb`
- Defensive Alliance: at most 12 turns and **at most 4 players** (`CFG_PROTECCION_MUTUA.MAX_JUGADORES 4`).
- Right of Passage: at most 8 turns.
- `MISC.PORCENTAJE_HOSTILIDAD_SITUACION_GUERRA 90`: a bar at 90 or above is a "war situation". Keep peaceful pairs at 88 or below.

### Hostility scale
- 0-100, **lower = friendlier**. The original allies sit at 40-45 and rivals at 55-60.
- The AI uses `get_grado_hostilidad` as 0..1.
- Treaty prices grow with the square of hostility (`MODIFICADOR_POR_RELACION`).
- Entries for players that are not in the game are ignored, because the loop runs over existing players.

### Area of influence / known countries
- These are not in the defs files. They are the **country `lists` (ring1, ring2) in mng section 3**, read by `Mng.parse_countries`.
- They correspond to `FACTOR_HOSTILIDAD_POR_DISTANCIA.ZONA_INFLUENCIA_1/2/3` (read at all.c ~547163). Zone 3, outside both rings, damps hostility changes (factor 0.2 for pre-revolutionary governments).
- They also bound `es_jugador_visible_diplomaticamente`, so they limit which players the AI can address.

Current mod:
- **JAPAN has empty ring1 and ring2**, so it is fully sakoku with no diplomatic contact.
- CHECHNYA's ring1 contains only RUSIA.
- The rings are asymmetric. For example, GB's ring1 contains QING and MYSORE.

Optional mng tweaks, not done here:
- JAPAN ring1 `[BATAVIA, QING, JOSEON]` (Dejima, the Nagasaki junks, Tsushima).
- CHECHNYA ring1 `+ OTOMANO, PERSIA`.

### Current mod files: not sensible
The files come from `tools\nations.py hostility()`, called from `make_map.py nation_files()`.

The 24 original blocks are unchanged and still carry the 1799-era treaties:
- GB-HANNOVER: now **Kazakhstan**.
- GB-ESPANYA.
- FRANCIA-BATAVIA.
- PRUSIA-SAJONIA: now **Sahara**.
- RUSIA-MOLDAVIA: now **Siberia**.
- AUSTRIA-RHELVETICA.

The three reskin alliances are nonsense now, and the bloc rule chains their partners in as well.

The 15 new nations:
- They are appended with `HOSTILIDAD 50.0` toward everyone and no treaties.
- The original blocks never mention them, so every original–new pair is a flat 50.

Other problems:
- Duplicate keys in the GB block: DINAMARCA (55/51) and BATAVIA (60/51).
- There are no wars at all.

## 2. What drives AI diplomacy

### Levers
| Lever | File | Effect |
|---|---|---|
| Profile per player | `IA/IADefs.sb`: `.JUG_X [ .DEFS_PRESIDENTE ... .DEFS_MINISTRO_DIPLOMATICO ... ]`. A missing key falls back to `.DEFAULT` (all.c ~588270, `FUN_00530800("DEFAULT")`). | Only the five empires have their own president profile. All other nations, the 15 new ones included, use `IA/Default/*`. The `#.JUG_ESPANYA`... entries are commented out. |
| Ministry weights | `IADefsPresidente.sb .PERFIL_PRIMARIO .PORCENTAJE_{MILITAR,ECONOMICO,DIPLOMATICO,TECNOLOGICO}` (sum 1) | Lua `get_prioridad_ponderada(mil,eco,dip)` weights every diplomatic order with these, so a higher `DIPLOMATICO` gives the diplomatic minister's vote more weight. |
| `UMBRAL_HOSTILIDAD_DECLARACION_GUERRA` (25), `TEMERIDAD` | IADefsPresidente | Declare war or invade without declaring (`Iniciativas_generate.lua generar_ordenes_guerra`). |
| Treaty prices | `IA/Default/IADefsMinistroDiplomatico.sb`: `.PRECIO_BASE_TRATADOS`, `.PRECIO_MINIMO_TRATADOS`, `.MODIFICADOR_POR_RELACION` | When the AI proposes, it offers 2×price (`generar_mensaje_*` in `diplomacy.lua`). When it receives, it accepts with p = offer/price − 1. Cheaper treaties mean more of them in both directions. |
| Anti-spam memory | `IADefsMinistroDiplomatico .MEMORIA`: `NUMERO_RECHAZOS_PARA_BLOQUEO 1`, `TURNOS_BASE_BLOQUEO 6`, ×1.5, max 30 | One rejection blocks that treaty type for 6 or more turns. This is the main reason the AI goes quiet. |
| Friendship gain per treaty | `DefReglasGenerales .BONUS_HOSTILIDAD_MENSAJES_DIPLOMATICOS` | Positive values make the parties friendlier. |
| Friendship from trade routes | `DefReglasComercio .BONUS_AMISTAD_TURNO_RUTA_SIMPLE/DOBLE` | Both are 0.0 today, so an open trade route never builds friendship. |
| Lua floors | `Game/LuaScripts/IA_Gestion/Iniciativas/Iniciativas_generate.lua preferencias_minimas_ordenes`: `alianza 0.05`, `paz 0.05`, `permiso_paso 0.1` | Minimum weighted preference before an order is sent. |
| Tech gates | `tiene_tecnologia_requerida_por_mensaje`; texts in `TextPantallaDiplomacia.sb` | Right of Passage needs Market Reform, Commercial Treaty needs Peaceful Annexation, Improve Relations needs Journalism, Military Aid needs Cultural Influence. Alliance, Coalition, Peace and War need nothing. |

### When the AI proposes what (Lua)
- **Defensive alliance:** `mejora_defensiva.lua generar_proteccion`. Sent to every diplomatically visible player while the AI's defence level is low (`TINC_NIVEL_MILITAR_DEFENSIVO_TERRESTRE_BAJO`).
- **Coalition:** against the most-attackable or most-hated player (`generate_iniciativa_asimilar` → `generar_ordenes_alianza`, `get_jugador_mas_odiado`). **Starting hostility therefore steers whom the AI gangs up on.**
- **Peace:** when at war (`generar_ordenes_paz`).
- **Right of passage:** to players at distance 1.
- **Marriage:** imperial players only.

## 3. The 1789 proposal

### How history maps onto game data
| History | Game data |
|---|---|
| Alliance | `PROTECCION_MUTUA 12`. Blocs of at most 4, kept disjoint. |
| War | `GUERRA` with hostility ≥ 90 |
| Tributary or vassal | No such state exists. Use low hostility, plus `PROTECCION_MUTUA` (Qing–Joseon) or `PERMISO_PASO 8` in both blocks (Qing–Siam, Ottoman–Egypt, Austria–Lombardy) |
| Trade agreement (Dejima, Canton) | No such state exists. Use friendlier hostility (Dutch–Japan 35; Qing 45–50 with the Canton traders), plus the trade-route friendship bonus above. |
| Isolation | High default hostility (Japan 65, Joseon 60, Ethiopia 58), the Aislado AI profile, and Japan's empty influence rings |

### Treaties at turn 1
| Bloc / pair | Data | Notes |
|---|---|---|
| GB + Portugal + Prussia + Dutch Republic (BATAVIA) | 3× PROTECCION_MUTUA 12 in the GB block | Anglo-Portuguese Alliance + Triple Alliance 1788. 4 members = full bloc. |
| France + Spain | PROTECCION_MUTUA 12 | Family Compact. Replaces the anachronistic GB–Spain. |
| Russia + Austria | PROTECCION_MUTUA 12 | 1781 alliance |
| Ottoman + Sweden | PROTECCION_MUTUA 12 | Treaty of 11 July 1789 |
| Qing + Joseon | PROTECCION_MUTUA 12 | Model tributary |
| Ottoman ↔ Egypt, Austria ↔ Lombardy, Qing ↔ Siam | PERMISO_PASO 8 | Suzerainty |
| Russia vs Ottoman | **GUERRA** | Russo-Turkish War 1787–92 |
| Austria vs Ottoman | **GUERRA** | Austro-Turkish War 1788–91 |
| Russia vs Sweden | **GUERRA** | Russo-Swedish War 1788–90 |

Removed: GB–Hannover, GB–Spain, France–Batavia, Prussia–Sajonia, Russia–Moldavia, Austria–RHelvetica.

**Why these three wars are acceptable at turn 1:**
- They are the defining conflicts of 1789.
- The sides are comparable: Russia+Austria against an Ottoman empire allied to Sweden.
- Prussia, GB and Poland are friendly to the anti-Russian side.
- No one-province nation is trapped.

Hostile but deliberately at peace:
- Chechnya (88 vs Russia): a single province whose only ring1 neighbour is Russia.
- Mysore (85 vs GB): the Third Anglo-Mysore War only began on 29 Dec 1789.
- Burma–Siam (80) and Maratha–Mysore (80).

The AI's own war logic decides whether these wars start. `--variant soft` drops every GUERRA and keeps those pairs at 88.

### Validator (in the script)
- War pairs are at 90 or above. Every other pair is below 90.
- Alliance blocs have at most 4 members, and no bloc contains a war.
- No pair of one imperial player and one neutral is below 25, which would invite peaceful annexation.

## 4. How to apply
1. Run `python build\diplo1789\make_diplo1789.py`.
   - `--variant soft`: no wars at turn 1.
   - `--lua`: also emit the Lua floors patch.
   - `--from-json`: regenerate the files from a hand-edited `diplomacy.json` (`defsIniciales.blocks`).
2. Copy `build\diplo1789\out\Game\...` over the same relative paths in the tree that is packed into Data2.pak. Do this after `make_map.py` has written `mod\`.
   - The four defs files **replace** what `nations.py hostility()` generates. Do not append to them.
   - Ship the new `IA/Aislado/` folder too.
   - For a permanent fix, change `make_map.py nation_files()` to copy these four files instead of calling `NT.hostility()`.
   - Also add the AI and rules files to the copy list. They are currently not in `mod\`, so the pak uses the originals.
3. Start a **new** campaign. The values are read only when a campaign is created.
4. Check in the Diplomacy window, under status and Degree of Hostility:
   - GB is allied with Portugal, Prussia and the Netherlands.
   - France is allied with Spain.
   - Russia and Austria are at war with the Ottomans.
   - Russia is at war with Sweden.
   - Japan has no contacts.
